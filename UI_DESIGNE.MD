# JobLink UI DESIGN SYSTEM

## Role

Act as a senior product designer with 10+ years of experience designing successful SaaS products.

Design JobLink as a **unique, polished, production-quality hiring platform**.

Do not create a generic job-board template.

The UI must feel intentionally designed for JobLink.

---

## 1. Design Philosophy

Prioritize:

* Clarity
* Simplicity
* Trust
* Speed
* Accessibility
* Strong visual hierarchy
* Excellent usability
* Consistency
* Distinctive visual identity

The interface should be attractive without sacrificing usability.

A new user should understand what to do without needing instructions.

---

## 2. Create a JobLink Identity

Establish a consistent visual language before building pages.

Define and consistently use:

* Brand colors
* Typography
* Spacing system
* Border radius
* Shadows
* Icon style
* Button styles
* Input styles
* Cards
* Badges
* Navigation
* Modals
* Tables
* Status indicators

Do not randomly invent styles on individual pages.

---

## 3. Avoid Generic AI Designs

Do NOT produce:

* Generic Bootstrap layouts
* Copy-pasted dashboard templates
* Excessive rounded cards
* Excessive gradients
* Excessive glassmorphism
* Random animations
* Huge empty hero sections
* Walls of text
* Too many cards
* Unnecessary shadows
* Tiny text
* Poor contrast
* Visually repetitive pages

Do not make every section look like a card.

Use whitespace, typography, layout, borders, imagery, and hierarchy to create visual interest.

---

## 4. User Experience

Every page must make these obvious:

**Where am I?**

**What can I do?**

**What should I do next?**

Primary actions must be visually obvious.

Common actions should require the fewest reasonable steps.

Avoid unnecessary navigation and unnecessary confirmation dialogs.

---

## 5. Landing Page

The landing page must immediately communicate:

* What JobLink does
* Who it helps
* Why users should trust it
* How to find opportunities
* How employers can hire

Create a strong visual opening rather than simply placing a heading and buttons in the center.

Use sections intentionally to guide the user toward:

**Discover → Explore → Apply**

and

**Post → Find → Hire**

---

## 6. Job Discovery

Job discovery is a core product experience.

Make searching and scanning jobs extremely easy.

Job cards should clearly expose the most important information:

* Job title
* Company
* Location
* Employment type
* Salary when available
* Experience
* Skills
* Posted date
* Save action

Search and filters must be visually accessible without overwhelming the user.

On mobile, redesign filters appropriately instead of shrinking the desktop layout.

---

## 7. Job Details

Prioritize the information users need to decide whether to apply.

Hierarchy:

1. Job title
2. Company
3. Location
4. Employment type
5. Salary
6. Important requirements
7. Description
8. Skills
9. Application action

The primary Apply action must always be easy to discover.

---

## 8. Dashboards

Do not build dashboards as collections of boxes.

Design dashboards around **user decisions and actions**.

### Job Seeker

Prioritize:

* Application progress
* Recommended opportunities
* Saved jobs
* Profile completeness
* Notifications
* Recent activity

### Employer

Prioritize:

* Active jobs
* Applicants
* Hiring activity
* Pending actions
* Interviews
* Important analytics

### Admin

Prioritize:

* Platform health
* Users
* Companies
* Jobs
* Moderation
* Important metrics

---

## 9. Navigation

Navigation must change according to the user's role.

Keep navigation:

* Predictable
* Minimal
* Clearly labeled
* Responsive

Do not expose irrelevant actions.

Desktop and mobile navigation should be intentionally designed separately.

---

## 10. Forms

Forms should feel effortless.

Rules:

* Group related information.
* Use clear labels.
* Keep fields understandable.
* Show validation beside the relevant field.
* Preserve entered information after errors.
* Clearly show required fields.
* Show submission progress.
* Provide useful success/error feedback.

Break complicated forms into logical sections.

---

## 11. States

Every meaningful component must consider:

### Loading

Use appropriate skeletons or progress indicators.

### Empty

Explain what is missing and provide the next useful action.

### Error

Explain the problem in human language and provide recovery.

### Success

Give clear confirmation without unnecessary interruption.

Never leave users staring at a blank screen.

---

## 12. Responsive Design

Design mobile-first.

The experience must work naturally on:

* Mobile
* Tablet
* Desktop

Do not simply compress the desktop layout.

Tables, filters, navigation, forms, cards, and dashboards must be intentionally adapted for smaller screens.

No horizontal scrolling unless genuinely necessary.

---

## 13. Accessibility

Use:

* Semantic HTML
* Keyboard navigation
* Visible focus states
* Proper labels
* Accessible forms
* Sufficient contrast
* Meaningful alt text
* Accessible dialogs
* Descriptive buttons

Never communicate important information using color alone.

---

## 14. Animation

Animation should have a purpose.

Use subtle motion for:

* Hover feedback
* Page transitions
* Dialogs
* Loading
* State changes

Never use animation merely because it looks impressive.

Respect reduced-motion preferences.

---

## 15. Component Design

Build a reusable design system.

Create reusable components for recurring patterns such as:

* Buttons
* Inputs
* Selects
* Cards
* Job cards
* Company cards
* Badges
* Avatars
* Tables
* Tabs
* Modals
* Toasts
* Pagination
* Search
* Empty states
* Loading states
* Error states

Do not duplicate nearly identical components.

---

## 16. Visual Hierarchy

Every screen should have one obvious primary focus.

Use:

* Typography
* Scale
* Spacing
* Position
* Contrast
* Grouping

to guide attention.

Do not make every element visually loud.

---

## 17. Content

Use realistic content when designing the interface.

Avoid:

* Lorem ipsum
* "Test User"
* "Job 1"
* "Company XYZ"
* Fake meaningless statistics

The UI should look believable during development.

---

## 18. Final Quality Standard

Before considering any UI complete, ask:

* Does this look like a real product?
* Is the primary action obvious?
* Can a first-time user understand it?
* Is the information hierarchy clear?
* Does it work on mobile?
* Are loading, empty, error, and success states handled?
* Is it accessible?
* Is it visually consistent with the rest of JobLink?
* Does anything feel unnecessary?
* Does anything look like a generic AI-generated template?

If the answer to the last question is yes, redesign it.

**Do not optimize for "it works."**

Optimize for:

**"It works, it is easy to use, and it feels like JobLink."**
